# LTA // UPLOAD — GitHub Windows App Guide

**What you're building:** Exactly the same pink-and-white LTA // UPLOAD Windows
application, now packaged by **GitHub Actions** into a portable Windows `.exe`.
No redesign, new screen, browser-app conversion or change to your beat workflow.

**What this project contains:** The full source code, a GitHub Actions workflow
(`.github/workflows/build-windows.yml`), the portable FFmpeg download/build
scripts, tests and instructions. **This ZIP is the GitHub project, not already
a finished Windows EXE**. GitHub makes the EXE after you upload the project.

## PART A — Put the project on GitHub (first time only)

### Easiest method: GitHub Desktop (recommended — preserves folders)

1. Make a free account or sign in at <https://github.com/>.
2. Download GitHub Desktop from <https://desktop.github.com/> and sign in.
3. Download and **extract** the `LTA_UPLOAD_GitHub_Project.zip` file.
4. Open the extracted `LTA_UPLOAD_GitHub_Project` directory in File Explorer.
   You should see `gui.py`, `core.py`, `README_FIRST.md` and a `.github` folder.
   **This exact folder is your repository root**; don't upload the outer ZIP.
5. In GitHub Desktop, choose **File > Add Local Repository** and select that
   folder. If told it is not a Git repository, choose **Create a Repository**
   at that location, name it `LTA-UPLOAD`, and create it.
6. If GitHub Desktop shows uncommitted changes, enter a summary such as
   `Add LTA UPLOAD Windows app` and click **Commit to main**.
7. Choose **Publish repository**. Select **Private** if you want to keep your
   project/source code private. Publish the repository.
8. On GitHub in your browser, open that repository. Confirm you can see:
   `.github/workflows/build-windows.yml`, `gui.py` and `requirements.txt`.
   The workflow file must be in **.github/workflows** at the repository root.

### Alternative: website-only upload

1. On GitHub, click **New repository**, name it `LTA-UPLOAD` and create it.
2. Choose **Add file > Upload files**. Upload the **contents of the extracted
   project**, maintaining `.github/workflows/build-windows.yml` in its exact
   folder path. Do **not** upload the ZIP as one file or put an extra folder
   around everything.
3. Commit to `main`, then confirm that `.github/workflows/build-windows.yml`
   is visible. Browser folder upload behaviour varies; use GitHub Desktop if
   `.github/workflows` does not appear intact.

## PART B — Make GitHub build LTA-UPLOAD.exe

1. In the GitHub repository, choose the **Actions** tab.
2. On the left, click **Build LTA UPLOAD for Windows**.
3. Click **Run workflow** (select branch `main`), then **Run workflow** again.
   A normal push to `main`/`master` can also start the workflow automatically.
4. Click the newest workflow run, then the **build-windows** job to read its steps.
5. When that run has a **green tick**, open its **Artifacts** section at the
   bottom of the run summary.
6. Download **LTA-UPLOAD-Windows**. It is a ZIP generated by GitHub.
7. **Extract the download**. It contains `LTA-UPLOAD.exe`, `ffmpeg.exe`,
   `ffprobe.exe`, `FFMPEG_LICENSE.txt`, `THIRD_PARTY_NOTICES.txt` and
   `START_HERE.txt`.
8. Put all those extracted files in one folder (e.g. `C:\LTA-UPLOAD`).
   **Don't separate the EXE from FFmpeg and FFprobe.**
9. Double-click **LTA-UPLOAD.exe**. Python and FFmpeg do **not** need to be
   installed separately for this GitHub-built portable version.

**Important:** GitHub builds the app on a Windows runner. The build requires
internet access to download Python packages and a Windows FFmpeg distribution.
A missing or failed third-party download can make an Actions run fail; in that
case see `GITHUB_TROUBLESHOOTING.md`. I have prepared the workflow but have not
run it inside your GitHub account or verified the final Windows EXE.

**Security on first launch:** Windows SmartScreen may warn about a new,
unsigned EXE. Check that it came from **your own GitHub Actions run** and scan
it before choosing to run; no code-signing certificate is included.

## PART C — Use the app (same workflow as before)

1. Drop an **MP3/WAV** into the left-hand area (or browse). You can add many.
2. Enter **Artist 1**, **Artist 2** and the **Beat name**; double-click a row
   to edit its beat name, BPM, key or direct BeatStars URL.
3. The app estimates BPM/key (manual corrections available), and generates a
   title such as `Fimiguerrero x Lancey Foux Type Beat - "He4rtB3at"`.
4. Choose your image / Pexels image / default artwork.
5. Review the static video preview, YouTube description, tags and publish mode.
6. On your **very first test**, untick YouTube and BeatStars assisted. Press
   **Generate & Upload** to produce a local MP4. There is no account access.
7. When the local video looks/sounds correct, connect your YouTube account
   (PART D). Test **Private** upload before choosing public/scheduled.
8. The generated video is a **still image with your full beat audio** — no
   animated visualiser, imposed watermark, extra mastering, EQ or compression.

## PART D — Connect your YouTube channel (one time, on your PC)

1. On your own PC, open <https://console.cloud.google.com/>.
2. Create/select a project, enable **YouTube Data API v3**.
3. Configure **Google Auth Platform** (consent screen, appropriate scopes,
   audience and any test users that Google requires).
4. Create OAuth credentials: **Client type = Desktop app**. Download the
   client JSON, then keep it **outside the GitHub repository**.
5. Open **LTA-UPLOAD.exe > Settings > Google OAuth desktop JSON** and point to
   that private local file. Save Settings.
6. Click **Connect YouTube**. Sign in in your actual browser and approve
   Google's OAuth flow. The app does NOT ask for your Google password.
7. Choose **Private**, tick YouTube, process a test beat and confirm it appears
   in YouTube Studio. Once working, choose Unlisted, Public or Scheduled.
8. For **Scheduled**, pick the local **Europe/London** date/time. Google native
   scheduling handles later publication; you can close the app afterwards.
9. Your local OAuth token stays in Windows Credential Manager. Do not commit
   the downloaded Google JSON, tokens, saved settings or private keys to GitHub.

**Note:** Google may apply restrictions to uploads from new or unverified API
projects. Titles, tags, thumbnails and scheduling are also subject to Google's
normal API, channel, access and quota limits. If upload status is uncertain,
check YouTube Studio before retrying to avoid a duplicate.

## PART E — BeatStars and Pexels (unchanged)

**BeatStars:** This is assisted publication; there is no claimed direct
BeatStars uploader. Select BeatStars assisted, use **Copy selected beat details
for BeatStars** and **Open BeatStars Studio**, upload there manually, and paste
the **direct BeatStars beat URL** back into the row. When YouTube is selected,
that individual beat link is included in the description. If missing with
BeatStars assisted selected, the app can skip the YouTube publish step until
it has the link.

**Pexels artwork search:** Obtain an API key from <https://www.pexels.com/api/>
and paste it into Settings. The key is stored locally in Windows Credential
Manager. You can still choose your own images without Pexels.

For more detailed settings, title templates, multiple-beat behaviour and
limitations, read the existing **README_FIRST.md**.

## PART F — Future updates through GitHub

1. Change your source files in the repository (or copy in an updated project).
2. Commit and **Push origin** with GitHub Desktop.
3. The GitHub Actions workflow starts another Windows build.
4. Download its newest **LTA-UPLOAD-Windows** artifact and replace the old
   EXE, FFmpeg and FFprobe together.
5. Your saved settings, artwork, channel connection and upload history normally
   survive the update because they live in `%APPDATA%\LTA_UPLOAD`, not in the
   EXE's folder. Keep backups of important local data.

**Cost/availability:** GitHub's availability, Actions quotas and retention
limits depend on your plan and repository settings. Artifacts expire; they are
not permanent download links. For a stable public release distribution later,
set up GitHub Releases separately.
